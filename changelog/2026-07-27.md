# 2026-07-27

## Added

- 增加 Main-owned Child Coordinator 和 Actor/Runtime 分离注册表，按 Checkpoint 幂等协调最多六个只读 Task。
- 增加不伪造 Attempt 的授权前失败结果，由 Store 原子写入 Task、审计 Event、Checkpoint rendezvous 与 ready Outbox。
- 增加按资源范围调度的共享只读 Child lease，支持最多三个并行任务、确定性优先级队列、deadline 和 cooperative cancellation。
- 增加无聊天消息持久化的 Child Runtime executor，以最小任务包、冻结模型和显式资源范围执行本地纯读工具。
- 增加 Main-owned 持久化 Turn 预算账本，优先预留 Primary 续接额度，并按 Task reservation 与实际 Attempt usage 幂等结算。
- 增加默认关闭的 Main-owned Primary 委派开关，仅在固定只读能力与三个并行 Child 上限下克隆注入可信 `delegate_task`。
- 增加真实 SQLite/Runtime 端到端回归，覆盖三个 Child 乱序读取、原调用顺序汇合、单次 Primary 续接以及消息、Attempt、Runtime 和 lease 清理。
- 增加仅供 Child 私有 overlay 使用的 `stage_file_write` 与 `stage_file_edit` 内部能力，并冻结 `atomic-file-v1` 提交适配器。
- 增加不可变 changeset、版本化 confirmation 和三阶段 commit journal 持久化事实，支持 hash 绑定、CAS 决议、崩溃恢复投影与原子终态汇合。
- 增加 Task/Attempt 私有磁盘 overlay、完整 unified diff 和 canonical changeset hash，在不修改真实工作区的前提下暂存受控文本创建与替换。
- 增加 resource-scoped `shared-read`、`write-intent` 与 `exclusive-commit` lease，支持 scope 兼容判断、writer fairness 和 phase-aware 幂等重放。
- 增加 Main-owned Child confirmation queue，以持久化 pending 事实、version CAS、diff integrity 校验和 Renderer 重载恢复管理多个并行确认。
- 增加 Child 文件提交器，以 durable journal、排他提交门禁、原子替换和目标 hash 复核应用已批准 changeset。
- 增加 commit journal 崩溃恢复，支持未落盘安全取消、部分落盘 roll-forward、已落盘 finalize 和未知状态人工恢复。
- 增加 Child 文件型受控写入端到端回归，以真实 SQLite、私有 overlay、持久化确认和 commit journal 证明批准前工作区不变、stale base 拒绝提交且默认门禁关闭。

## Changed

- delegation Outbox 改为先交付强制 Main 内部消费者，再发布 Renderer 投影并确认 delivered；主进程在 IPC 开放前恢复 Coordinator 并重放 pending Outbox。
- Coordinator 改为只在取得 lease 后进入受控执行缝，并在执行完成、启动失败或中止时幂等释放调度许可。
- Runtime stream 在接受 Provider 工具结果或调用本地 executor 前执行强制来源感知门禁；预算超限结果可保留真实 usage，其他终态仍受冻结预算约束。
- Coordinator 接通 Attempt、Child Runtime、结果汇合与预算结算完整链路；deadline 统一取 Task、Turn 和系统 Child 时限的最小值。
- cooperative cancellation 先持久化 `cancelling`，再传播 signal，并以有界等待和宽限期 hard abort 收敛；取消中的结果不会创建 Primary 续接 Outbox。
- 启动恢复会先中断不可恢复 Checkpoint 并释放其预算 reservation；Outbox 交付前重新校验持久化状态，避免终态、tombstone 或过期事件重启 Child。
- Execution Plan 校验、能力交集与恢复改为按 read/write mode 收缩；write 计划必须保留 staged 能力并使用固定提交策略。
- 委派服务与 Coordinator 统一切换到 mode-aware `authorizeTask()`，并移除临时只读兼容入口。
- write Child 工具集按调用重验 Runtime、registry、冻结能力、资源 scope 和取消信号，并允许 staged Plan 继续复用计划内 pure-read 能力。
- Coordinator 接通 write Child 的 changeset preparation、持久化确认、`queued(commit)`、排他提交和 finalized rendezvous；确认等待期间不持有资源 lease。
- BChat confirmation 改为应用级风险优先/FIFO 投影；Runtime resolver 保持 controller 私有，Child Agent 仅暴露一次性批准/拒绝和经 allowlist 裁剪的 changeset 事实。
- commit journal 在创建时把候选与回滚内容复制到私有恢复目录；Store 允许 protected reference 替换但继续精确绑定全部批准操作事实。
- 增加独立 Main-owned `controlledWriteChildEnabled` 灰度门禁，默认和生产配置保持关闭，测试必须显式开启。
- confirmation 拒绝、取消撤销、commit 前 stale context 和 journal 后迟到取消均按合法状态迁移收敛；迟到取消保留 completed 结果并追加 `cancel_arrived_too_late` warning。
- Main 启动按 commit journal、confirmation、未提交 overlay/Checkpoint、Coordinator 的顺序恢复；恢复完成前 write Task 保持 queued，不创建 Runtime。
- Coordinator 在进入提交器前从 Store 重读 approved changeset 权威投影并复核 snapshot hash，避免复用确认前的内存状态。
