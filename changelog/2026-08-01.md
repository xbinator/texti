# 2026-08-01

## Added

- 聊天消息 IPC 增加单条删除能力，用于在不覆盖活动流历史的前提下精确清理旧版本误写的恢复提示。

## Changed

- 聊天会话删除统一增加确认流程；运行中删除会先终止 Main Runtime 与 Child Checkpoint，并由主进程锁断言阻止未收敛删除。
- 补齐聊天侧边栏 Runtime 状态投影，删除按钮在所有运行状态下保持可用且不使用禁用属性。
- 聊天会话历史增加运行中与等待操作状态图标，并按运行、等待和其他状态显示对应的删除确认文案。
- Renderer 本地确认也会将会话投影为等待状态；同一会话存在多个并发确认时，需全部处理后才恢复运行状态。

## Fixed

- 修复切换并重新打开仍在流式生成的会话时，未完成 assistant 草稿被误判为硬中断并新增“已中断”提示的问题；恢复前现在同时检查活动 Runtime 与 Agent Checkpoint，并在状态查询失败时保守保留草稿。
- 修复快速执行 A→B→A 会话切换时，第一次 A 的旧历史响应覆盖第二次 A 最新消息的问题。
- 活动 Runtime 重新接管会话时会识别并删除旧版本已持久化的伪硬中断提示，同时保留真正的用户中止记录。
- 修复会话切换后旧异步预检恢复执行、预检 loading 未及时释放，以及空白草稿重置后仍可能启动 Runtime 的问题。
- 修复请求预检期间切换 WebView 或编辑器时，能力描述与 Runtime 绑定到新资源的问题；资源身份现在从预检开始即冻结，后台工具只访问该 Runtime 的固定资源。
- 修复后台 Runtime 启动失败错误落到当前可见会话、再生成在破坏性持久化后因切页停止的问题。
- 修复确认决议 IPC 失败后界面永久消失、记忆授权失败后无可见降级、终态确认被重复提交，以及并发确认缓存相互覆盖的问题。
- 修复恢复阶段首次重放失败后不再重试，以及跳过失败请求继续执行后续请求导致原始顺序被破坏的问题。
- 修复删除会话后 Renderer Actor、Runtime 路由、能力与确认缓存残留的问题；显式 Session 已删除时，Main 会拒绝迟到的 Runtime 启动，防止产生孤儿消息。
- 修复会话删除成功但 fallback 导航被阻止时仍保留陈旧标签与 Runtime 投影的问题。
- Agent confirmation 终态游标改为最多保留最近 512 个，并将权威恢复中消失的 pending 请求终态化，避免游标长期无界增长和迟到事件复活。
- Runtime 恢复在第二份权威快照重放失败后增加 50ms、100ms 两次有界退避，同时保持请求原始顺序并在耗尽后抛出最后错误。
