# Markdown 初始加载撤销基线设计

## 背景

编辑器页面会先以空白 `fileState` 挂载 `BEditor`，随后异步读取磁盘文件并把整篇 Markdown 同步到已经创建的 Rich 或 Source 编辑器。两种编辑器都把这次全文替换记录为一次普通编辑，因此用户可以通过 `Ctrl+Z` 从磁盘内容继续撤销到空白文档。

磁盘加载结果应当是编辑会话的初始基线，而不是用户操作。首次打开文档后，撤销栈必须为空。

## 目标

- 初始文件加载期间不创建 `BEditor`。
- 加载完成后直接用最终 `fileState.content` 创建 Rich 或 Source 编辑器。
- 首次加载的磁盘内容不进入撤销栈。
- 用户加载完成后的编辑仍可正常撤销和重做。
- 文件监听收到的外部磁盘更新仍沿用现有同步与冲突处理，并保留可撤销语义。
- 新建空白文档继续在加载完成后自动聚焦编辑器开头。

## 非目标

- 不改变 Rich 和 Source 编辑器内部的历史插件配置。
- 不改变粘贴、AI 全文替换、选区替换等用户动作的撤销语义。
- 不重构文件控制器、草稿恢复或磁盘冲突处理流程。

## 方案

在 `src/views/editor/index.vue` 的 `BEditor` 上增加加载门控，仅当 `isLoading` 为 `false` 时挂载编辑器。

文件控制器在页面首次渲染前会进入加载状态。磁盘读取、草稿调和和冲突选择完成后，控制器先原子更新 `fileState`，再结束加载状态。Vue 随后第一次创建 `BEditor`，因此子编辑器构造时已经拿到最终内容：

1. `useSession` 创建空白会话并启动异步加载。
2. `isLoading` 变为 `true`，页面暂不挂载 `BEditor`。
3. 文件控制器读取并调和草稿与磁盘内容。
4. 文件控制器更新 `fileState`，然后把 `isLoading` 设为 `false`。
5. 页面以最终内容挂载 `BEditor`；编辑器历史从空栈开始。

外部文件监听的普通内容变化不会进入页面级加载状态，因此已经挂载的编辑器保持现有更新行为。存在未保存修改时仍由文件控制器执行冲突确认，不会静默覆盖用户内容。

## 组件影响

- `src/views/editor/index.vue`
  - 根据 `isLoading` 控制 `BEditor` 是否挂载。
  - 保留现有 `:key="fileState.id"`、事件绑定、滚动恢复和空白文档聚焦逻辑。
- `src/components/BEditor/**`
  - 无需修改。Rich 和 Source 编辑器继续使用各自现有的历史实现。
- `src/hooks/useFileController/**`
  - 无需修改。继续保证先应用文件快照，再结束加载状态。

## 测试设计

在编辑器页面组件测试中增加回归用例：

1. `isLoading` 为 `true` 时，页面不渲染 `BEditor`。
2. 测试更新最终文件内容并把 `isLoading` 切换为 `false` 后，页面只挂载一次 `BEditor`，且首次收到的是加载后的 Markdown 内容。
3. 保留并运行现有 KeepAlive 滚动恢复和空白文档自动聚焦测试，确认加载门控没有破坏生命周期行为。

测试通过首次挂载内容证明编辑器不会经历“空白 → 磁盘全文”的外部替换事务；Rich 和 Source 的构造路径都因此获得空撤销栈。

## 验收标准

- 打开已有 Markdown 文件后立即按 `Ctrl+Z`，内容保持不变。
- 修改内容后按 `Ctrl+Z`，最多撤销到文件刚打开时的内容，不会撤销成空白。
- Source 与 Rich 模式行为一致。
- 新建空白文档加载完成后仍自动获得输入焦点。
- 外部文件变化和未保存内容冲突处理保持现状。
