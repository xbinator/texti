# WebView 全页截图定位层刷新设计

## 背景

WebView 全页截图会逐屏滚动页面、隐藏 `fixed` / `sticky` 定位层并拼接基础切片，最后只回填首屏顶部栏和末屏底部栏。当前定位层只在截图开始前扫描一次，因此首屏尺寸为零、滚动后才显示或第二屏动态创建的定位元素不会获得截图标记，也不会被后续隐藏规则命中。

## 目标

- 每个截图切片滚动完成后，发现并标记当前 DOM 中新出现的 `fixed` / `sticky` 元素。
- 第二屏及后续中间屏出现的定位层不进入最终长图。
- 继续保留首屏吸顶定位层和末屏吸底定位层。
- 截图完成或失败后，恢复页面滚动位置并清理全部临时属性和样式。

## 非目标

- 不改变当前全页截图的切片和 Canvas 拼接算法。
- 不把 `fixed` 元素转换为普通文档流元素。
- 不改变选中元素截图和当前视口截图行为。
- 不引入 `MutationObserver` 或持续监听页面 DOM。

## 方案

### 定位层扫描

将 `src/views/webview/web/utils/screenshot.ts` 中的定位层扫描设计为可重复执行的增量操作：

- 首次执行时创建截图控制样式节点。
- 每次执行都扫描当前 DOM 的可渲染元素。
- 已标记元素保留原有标记；新出现且计算定位为 `fixed` / `sticky` 的元素补充相应标记和唯一标识。
- 唯一标识在多次扫描之间保持稳定，避免同一元素因重扫获得不同身份。

### 切片采样顺序

`src/views/webview/web/hooks/useScreenshot.ts` 中每个切片按以下顺序处理：

1. 滚动到切片位置并等待页面完成两帧绘制。
2. 恢复定位层原始状态。
3. 重新扫描并补标当前屏新出现的定位元素。
4. 读取当前屏可见定位层快照。
5. 隐藏全部已标记 `fixed`，并将已标记 `sticky` 暂时解除吸附。
6. 截取不含中间定位层的基础切片。

定位层覆盖计划继续使用现有规则：只从第一屏观测中选择顶部元素，只从最后一屏观测中选择底部元素。中间屏观测仅用于确认定位层已被识别，不回填到最终长图。

### 清理与错误处理

现有 `finally` 清理流程保持不变，负责移除所有扫描阶段添加的属性、删除控制样式并恢复截图前滚动位置。重复扫描不新增独立监听器或异步资源，因此无需额外销毁逻辑。

## 测试

在 `test/views/webview/web-use-screenshot.test.ts` 增加回归覆盖：

- 元素在首屏不可见、滚动到第二屏后变为可见且计算定位为 `fixed` 时，增量扫描会补充标记，隐藏脚本能够命中它。
- 第二屏动态插入的 `fixed` 元素同样会被后续扫描标记。
- 全页截图对每个切片都执行定位层刷新，而不是只在截图开始前扫描一次。
- 现有首屏顶部、末屏底部保留规则不变。

验证范围包括目标 Vitest 测试、ESLint、Stylelint 和 TypeScript 类型检查。
