# 会话级临时工作区设计

## 背景与目标

Tibis 目前始终把 `~/.tibis` 作为 ChatRuntime 的工作区根目录。用户需要在独立聊天页中为单个聊天会话选择一个本地目录，并将它作为该会话后续运行时的工作区。

该选择是会话级覆盖，而不是全局设置：没有选择目录的会话继续使用 `~/.tibis`；不同会话互不影响；重新打开会话或重启应用后仍能恢复选择。

## 方案选择

采用“会话元数据 + 原生目录选择器”方案。

- 将可选的 `workspaceRoot` 写入 `ChatSessionMetadata`，复用现有 `chat_sessions.metadata_json` 字段，无需数据库迁移。恢复默认工作区时删除该字段，而不是写入默认目录。
- 在输入工具栏中提供工作区入口，使用主进程原生目录选择对话框选择目录。
- Runtime 请求使用会话保存的目录；缺失时回退到默认 `~/.tibis`。

未采用独立本地缓存，因为它会脱离会话生命周期且难以跟随会话删除、分支与迁移；未采用全局设置，因为它不能保证会话隔离。

## 组件与数据流

### 会话持久化

`ChatSessionMetadata` 新增明确的可选 `workspaceRoot` 字段。主进程增加专用的会话工作区更新与清除 IPC：更新时合并 metadata，清除时只删除 `workspaceRoot` 并保留模型等其他 metadata；渲染进程的 session store 提供对应 action 并以主进程返回的完整会话更新本地缓存。

新会话在首条消息发送前还没有会话 ID，因此 BChat 保留草稿级选择。创建会话时，草稿工作区和模型一并写入 metadata。已有会话读取 metadata 后恢复选择。由现有分支流程复制 metadata，因此分支会话继承源会话的工作区。

### 工作区选择与有效根目录

新增原生“选择目录” IPC，并在主进程通过 realpath 规范化为真实的本地目录。会话创建与工作区更新 IPC 也会在主进程再次执行 realpath 和目录校验，确保其他渲染进程调用路径不能写入未规范化、失效或文件类型的工作区。用户取消选择时保留当前选择。

BChat 增加一个会话工作区 composable，维护草稿选择、已加载会话选择及有效工作区根目录：

1. 读取会话 metadata 中的 `workspaceRoot`。
2. 如果存在则作为有效根目录；否则使用 `useRuntimeTools` 当前提供的默认 `~/.tibis` 根目录。
3. 切换目录后先完成主进程选择和规范化，再持久化到当前会话；草稿会话只更新本地状态，等首次发送时持久化。
4. 恢复默认工作区时，草稿会话清除内存选择；已有会话清除已保存的 `workspaceRoot`，使当前及后续打开都使用默认根目录。
5. 已有会话的 workspaceRoot 仍在读取时，Runtime 请求等待读取完成；读取失败则阻止请求，绝不把读取失败误判为“使用默认工作区”。

现有 Runtime、工具可用性筛选、文件引用解析和请求配置均接收该有效根目录，因此不需要为每个工具另建分支。一次 Runtime 启动时已创建的请求继续使用启动时冻结的根目录。

### 界面交互

`InputToolbar` 在工具栏左侧提供可选的工作区控件胶囊；通用 BChat 默认不显示该控件，只有 `src/views/chat/index.vue` 的新会话草稿态显式启用，已有会话、聊天侧栏等其他宿主不可选择或清除工作区：

- 胶囊高度为 `28px`、圆角为 `18px`；默认透明，鼠标移入或键盘聚焦时才显示统一浅色背景。工作区名称与恢复操作共享同一背景，不使用边线、间隙或两个独立圆角，避免分割感。
- 名称和恢复操作使用原生 HTML `button`，不使用 `BButton`；名称按钮左侧显示 `lucide:folder-closed`，并展示当前工作区名称：未覆盖时表示默认工作区，覆盖时展示所选目录的可识别名称；不渲染 tooltip、`data-testid` 或 `aria-label`。
- 点击文字按钮打开目录选择对话框。
- 已有临时覆盖时，鼠标移入工作区控件胶囊时，以同一左侧图标槽位的 `x` 覆盖 `lucide:folder-closed`；点击后清除当前会话保存的临时目录，名称不移动。没有覆盖时不显示该图标。
- Runtime 正在运行、等待用户交互或回退时禁用选择与恢复，防止改变运行中任务的文件权限边界。
- 切换成功后立即更新当前会话的显示与后续请求；其他会话保持自身值或默认值。

## 异常处理

- 目录选择取消：不修改内存或持久化状态。
- 主进程规范化失败或路径不再是目录：不保存选择，并在 BChat 显示错误提示。
- 已保存目录在以后被删除或不可访问：仍保留会话 metadata，以便用户能看见原选择；后续运行前的目录校验失败会阻止该请求并提示用户重新选择工作区。不会静默回退到 `~/.tibis`，以免在错误目录执行文件或 Shell 工具。
- 已有会话的 workspaceRoot 无法从持久化存储读取：阻止请求并提示稍后重试，不会静默回退到 `~/.tibis`。
- 切换会话时异步加载结果必须按会话 ID 校验，避免旧会话结果覆盖当前选择。

## 验收与测试

- 新会话在第一条消息前选择目录后，创建的会话 metadata 包含规范化后的 `workspaceRoot`，该运行时使用它。
- 已有会话切换目录会持久化，重新打开和应用重启后恢复。
- 两个会话选择不同目录时，请求各自使用正确根目录；未选择的会话继续使用 `~/.tibis`。
- 从带工作区的会话创建分支后，分支继承该工作区。
- 草稿与已有会话恢复默认工作区后，都不再保存 `workspaceRoot`，且模型等其余 metadata 不受影响。
- 工作区控件仅由独立聊天页的新会话草稿态启用，位于工具栏左侧；名称与 `x` 恢复操作组成高度 `28px`、默认透明的 `18px` 圆角胶囊，悬停或聚焦时显示统一背景，名称使用 `12px` 字号，且不使用 `BButton`、tooltip、`data-testid` 或 `aria-label`；临时覆盖存在时，悬停在原文件夹图标位置显示恢复操作。
- 取消目录选择、非法目录、目录失效以及运行中尝试切换都有可预期且安全的结果。
- 会话元数据读取未完成时请求会等待；读取失败时请求被阻止。目录选择与文件选择并发时各自返回正确的结果类型。
- 覆盖 session store、会话工作区 composable、主进程 IPC/服务和工具栏交互的单元或组件测试；运行 TypeScript、ESLint 和 Stylelint 检查。
